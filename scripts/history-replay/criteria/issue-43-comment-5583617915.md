### Output / behavior delta

**Picker navigation and editing**

- Up/Down select previous/next visible match; Tab/Shift-Tab are aliases. At the first/last match, stop rather than wrap. With no match, navigation is a no-op. None of these keys inserts text, captures a file, submits or calls the model.
- Left/Right move the query cursor by extended grapheme cluster; Backspace deletes the preceding cluster. Printable input inserts at that cursor. Home/End may place the query cursor at its boundaries, but cannot insert escape sequences. Use the product's Node runtime grapheme segmentation without a new dependency; include CJK, combining marks and emoji-ZWJ in fixtures.
- After a query edit, recompute matches and choose the first result if any; after a pure cursor move, preserve the selected result. Query and cursor must be visible through a safe rendered query editor/marker; if a terminal cursor is not used for the query, a clearly separate position indicator must unambiguously identify the insertion point without modifying the query itself. Unknown non-text keys are no-ops, not raw control bytes in search.
- Listing/capture asynchronous states must be distinct. During listing, retain permissible query edits, but Enter cannot capture until results exist. During capture, ignore further navigation/confirmation; Escape/Ctrl-C retains the existing cancellation behavior, and a late completion must not attach or submit after cancellation. No new auto-submit mechanism.
- Enter in the picker selects only and returns to the existing composer. Escape continues the 1.0 literal-@query dismissal path; Ctrl-C continues picker cancellation without losing the original draft/selected attachments. Outside the picker, retain current key behavior: this repair does not introduce global Tab focus cycling, multiline input or a fullscreen editor.

**Submission feedback**

- After successful selection, duplicate selection, removal, inline preview return, or an idle local command, show a concise persistent hint beside/above the editable prompt: **`Not submitted · Enter Send`** when a nonblank task can be sent; **`Not submitted · Write a task`** for attachment-only/blank draft. An equivalent English formulation is allowed if both facts remain explicit.
- If a selected next-draft exists while a task is running/cancelling, label it unsubmitted/busy rather than inviting immediate sending. Busy Enter still retains the draft and never queues it. Do not alter cancellation/execution semantics.
- Keep existing preview interaction: Ctrl-P / :preview prints the safe full snapshot and returns to input. This repair need not add a modal preview or another confirmation key. Finishing that preview cannot send a task; a later, separate composer Enter is the send action. Selecting/previewing with zero Faux exchanges is correct until that action.
- With no submitted run, :details says **`No submitted run yet`** (or equivalent), rather than implying a failed model run. :runs with an empty archive likewise explains that nothing has been submitted. The local command does not itself create a Run; after it returns, preserve the draft's attachments and present the relevant send/write hint. Existing local-command draft editing semantics are retained, not silently redesigned.
