### Output / frozen behavior

1. Native compact TUI supports an idle-draft `@` picker, literal path search, keyboard selection, Escape cancellation and attachment removal. Picker Enter selects only; task submission remains a separate action. Literal email/@ text never reads or attaches files without explicit selection. Help explains the keys and an explicit literal-text escape/dismiss path. Existing busy-Enter keeps a draft and never queues a task; picker and draft state must not accidentally submit after cancellation.
2. Search enumerates names/metadata, never file contents. Candidates are workspace-relative regular files; dot-prefixed path components and symbolic links (including directory components) are excluded. In a Git workspace honor repository ignore rules for untracked files and include non-hidden tracked regular files; in a non-Git workspace enumerate non-hidden regular files without symlink traversal. Do not silently fall back to broader discovery if the Git-aware listing fails. No recursive content scanning, follow-links option, absolute/outside-workspace attachment or ignore override in v0. Use literal arguments, not shell interpolation, for discovery. These are attachment-selection rules, not a sandbox claim or changes to trusted-local tool authority.
3. Selection reads only the explicitly chosen eligible regular file into an immutable in-memory snapshot. Record workspace-relative path, SHA-256 of original bytes, exact byte count and UTF-8 content; preserve BOM/newlines/Unicode with round-trip byte equality. Reject invalid UTF-8, NUL-containing binary, directories/devices/FIFOs, missing/unreadable files and a detected replacement/change during capture with a typed local error and no admitted task. Reject paths that resolve outside the workspace or through symlinks; do not claim protection against arbitrary concurrent malicious host mutation.
4. Show selected path, byte count and snapshot identity before submit; provide a full safe content-preview action. Make it explicit that submit sends the selected snapshot and stores it in the Run Archive. Later disk edits/deletion do not silently refresh a snapshot: send the captured bytes, labelled snapshot; remove/reselect deliberately refreshes it. No file reread on submit or replay. Selecting the same relative path twice must not silently duplicate it; keep one attachment and offer explicit refresh/removal.
5. `maxAttachmentBytes` is a positive safe-integer configuration (reject boolean/zero/negative/fraction/unsafe values before selection). Default **1,048,576 bytes** aggregate per draft, inclusive; sum the original byte lengths of distinct selected snapshots. This is a Master-selected v0 local attachment resource policy (1 MiB), not a measured model context limit or token cutoff. Provide a documented startup override. Bounded reading must detect limit+1 without loading an arbitrarily large file; failure preserves the prior draft/attachments. Never truncate or summarize file content. Larger explicitly configured attachments remain subject to existing model-context failure behavior; this issue adds no compaction/retry.
6. With no selected attachment, submit the original task byte-for-byte as before. With attachments, a small input-preparation module creates a versioned, losslessly decodable task envelope containing the original prompt and ordered attachment records. The envelope remains **user-supplied data**, never system text, executable ToolCall or Provider-private fields. Require exact round-trip of prompt/path/hash/bytes/text and delimiter-like file content; the concrete encoding is Builder-owned and documented before Handoff. Reuse the existing task string and run.started.task storage; no Canonical Protocol, Kernel or durable record/manifest schema change is needed or authorized. Archive/replay displays metadata/content from this recorded envelope, not today's workspace. Old tasks that resemble an envelope must not crash or be silently reinterpreted as new attachment metadata: recognition requires the full versioned shape and integrity checks, otherwise show ordinary task data.
7. Pan-owned UI labels remain English. Human/file/model data retain their language. Default display shows attachment summaries, not a dump of all attached contents; full content is available through an explicit inspect action. Render all untrusted filenames/errors/content through the accepted terminal-safe boundary, with framing for multiline content. Explicit attachments are user data: selecting a file does not grant it a trusted instruction role, and attaching secrets deliberately is not made safe by filename filtering. Do not read Provider credentials or implicit process environment into any attachment.
