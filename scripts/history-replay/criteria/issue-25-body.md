## Outcome

Make the accepted TypeScript general-agent stack preserve three different kinds of memory with three different mutation rules:

1. **Run Archive** — raw execution history is append-only while a run is active, then sealed and read-only.
2. **Retrospective Ledger** — conclusions and corrections are append-only and remain linked to the source run.
3. **Runbook** — current operating guidance is editable, diffable, and reversible under version control.

This WorkOrder turns the Human's accepted rule — “raw trajectories are read-only archives; retrospective cognition only grows; execution manuals may be patched and rolled back” — into executable product behavior.

## Current gap

The accepted TypeScript session currently keeps observations in memory and explicitly does not provide a durable event log or replay. The older Python evented path contains partial append-only/replay machinery, and the Wiki has an append-only maintenance log, but neither establishes this contract for the authoritative TypeScript working stack. Current documentation is also not divided into a general run-linked Retrospective Ledger and a separately mutable Runbook.

## Domain contract

### Run Archive

- Contains the exact ordered canonical trajectory needed to explain a run: run identity, model/profile identity, runbook revision, semantic messages/events, typed tool requests/results, usage where reported, and terminal or interrupted settlement.
- Is append-only while active. A terminal, cancelled, failed, or interrupted run is settled and sealed; it is never silently reused or overwritten.
- After sealing, normal application interfaces expose read and replay only. Mutation or deletion attempts must fail, and integrity metadata must reveal byte-level tampering.
- Raw does not mean public: credentials must never be stored; restricted fields must not appear in normal TUI or public projections.

### Retrospective Ledger

- Stores post-run interpretation separately from the raw archive.
- Every entry references a sealed Run Archive identity and integrity hash.
- Entries are append-only. A correction creates a new entry with an explicit `supersedes` reference; it never edits or deletes the earlier cognition.
- A retrospective entry is not automatically a verified project fact.

### Runbook

- Represents current best operating instructions.
- Is intentionally mutable through ordinary version-controlled edits, diffs, and reverts.
- Every Run Archive records the exact Runbook revision/hash used, so later Runbook changes never rewrite the meaning of an old run.
- A retrospective may propose a Runbook change, but cannot mutate the Runbook implicitly.

These names and boundaries must be added to the project domain glossary so later work does not collapse evidence, interpretation, and current instructions into one document type.

## Deliverables

- Versioned Runbook identity captured by each run.

## Acceptance criteria (Criteria-Version `1.0`)

Every criterion below is **blocking** and evaluates to `PASS | FAIL | NOT_EVALUABLE` under the Operational Acceptance Criteria contract in `docs/governance/verification.md` (itself Criteria-Version `1.0`, landed at the base above). Acceptance requires every blocking Criterion to PASS. Handoff and Verdict must both name Criteria-Version `1.0`.

**GateLevel:** `high-risk` for C-MEM-03 (deletion-related) and C-MEM-06 (credential-related); the Regulator review must therefore be a different model family or explicit Human review per `verification.md`. All other criteria are `standard` depth inside the same review.

### C-MEM-01 — Archive-before-side-effect invariant (oracle: deterministic invariant/test)

- **Given:** the candidate TypeScript `GeneralAgentSession`/TUI path driven by deterministic fake Provider and tool adapters, over the open domain of non-empty tasks.
- **Observe:** durable archive records and their causal positions relative to the first Provider exchange and first tool effect of each probe run.
- **Pass iff (domain invariant):** for every admitted non-empty run, a uniquely identified durable Run Archive exists and its first durable record is appended before any Provider exchange or tool side effect of that run; run identities never collide and are never reused. Minimum probe coverage: one normal run, one Provider-failure run, one tool-failure run, one cancelled run.
- **Fail when:** any probe reaches a Provider exchange or tool effect without a prior durable archive record, or a run identity collides or is reused.

### C-MEM-02 — Causal append-only prefix and interrupted settlement (oracle: deterministic invariant/test)

- **Given:** active runs interrupted at predeclared crash points — between two event appends, during a single record write, and after a cancellation request — using temporary test directories.
- **Observe:** on-disk archive bytes after the interruption.
- **Pass iff:** durable records form a causal-order prefix of the run's event sequence; each interruption settles the run with a distinct interrupted/incomplete settlement marker; no durable record is overwritten, reordered, or silently dropped; the interrupted run's identity is never reused.
- **Fail when:** any probe shows a suffix without its prefix, reordered records, a missing settlement marker, or identity reuse.

### C-MEM-03 — Sealed archive immutability (GateLevel: high-risk; oracle: deterministic invariant/test)

- **Given:** archives settled in each of the four states: terminal, cancelled, failed, interrupted.
- **Observe:** results of append, overwrite, and delete attempts through every application-owned write interface; the Handoff must enumerate those interfaces.
- **Pass iff:** every attempt is rejected with a typed refusal and the archive bytes are byte-identical afterwards, across all four states × all enumerated write interfaces.
- **Fail when:** any attempt mutates or deletes any archive byte, or an application-owned write path remains unenumerated.

### C-MEM-04 — Integrity tamper detection (oracle: deterministic invariant/test)

- **Given:** a sealed archive and four tamper classes: modified record bytes, deleted record, reordered records, injected record.
- **Observe:** the integrity verification verdict for the pristine archive and for each tampered variant.
- **Pass iff (domain invariant):** any byte-level deviation from the sealed integrity metadata is reported as an integrity failure, and the pristine archive verifies clean. Minimum probe coverage: the four tamper classes above.
- **Fail when:** any tampered variant verifies as valid, or the pristine archive fails verification.

### C-MEM-05 — Zero-effect replay/inspect (oracle: deterministic invariant/test)

- **Given:** valid archives produced by the C-MEM-01 probes plus at least one corrupted archive.
- **Observe:** instrumented counts of Provider exchanges and tool effects during list, inspect, and replay operations, and the behavior on corrupted input.
- **Pass iff:** both counts are exactly `0` for every operation and input, and corrupted input yields a typed failure — not a side effect and not an untyped crash. The counts are exact-zero predicates, not statistical thresholds.
- **Fail when:** any count is greater than `0`, or corrupted input causes an effect or an untyped crash.

### C-MEM-06 — Canonical completeness with credential exclusion (GateLevel: high-risk; oracle: deterministic invariant/test)

- **Given:** archives of runs exercising every event kind in the candidate's declared event taxonomy, with a predeclared set of canary credential strings (fake secrets in a declared format) present to the fake Provider adapter.
- **Observe:** (a) the replayed reconstruction against the recorded semantic event sequence; (b) a byte scan of all archive artifacts for canary credential material; (c) normal TUI and public projections of restricted fields.
- **Pass iff:** reconstruction preserves the canonical semantic information of every declared event kind; no canary credential byte sequence appears in any archive byte; restricted fields never appear in normal or public projections.
- **Fail when:** any event kind loses canonical semantic content, any canary byte sequence appears in an archive, or any restricted field renders in a normal/public projection.

### C-MEM-07 — Retrospective reference integrity and supersession-only mutation (oracle: deterministic invariant/test)

- **Given:** one sealed archive, one active (unsealed) archive, and the Retrospective Ledger.
- **Observe:** entry admission results and the enumerated ledger interfaces.
- **Pass iff:** entries referencing a nonexistent or unsealed archive identity, or a mismatched integrity hash, are rejected; valid entries are admitted; a correction is stored as a new entry carrying an explicit `supersedes` reference to the earlier entry; the enumerated ledger interfaces contain no update or delete path.
- **Fail when:** an invalid reference is admitted, a correction mutates the earlier entry, or any update/delete path exists.

### C-MEM-08 — Retrospective is not raw trajectory and not auto-promoted (oracle: deterministic invariant/test plus file-identity check)

- **Given:** a ledger holding at least one entry and one superseding correction.
- **Observe:** (a) the result of feeding ledger entries into the Run Archive replay/reader interfaces; (b) `docs/evidence/verified-project-facts.md` compared against the accepted base.
- **Pass iff:** ledger entries are typed distinctly from archive records and are rejected as trajectory input by archive readers; `docs/evidence/verified-project-facts.md` is byte-identical to the accepted base `c366060a706ddbf1905943eed8d4aa029837e8c2`.
- **Fail when:** a ledger entry is accepted as raw trajectory by any archive interface, or the fact register differs from the base.

### C-MEM-09 — Runbook revision binding (oracle: deterministic invariant/test)

- **Given:** a versioned Runbook with at least two edits and one revert.
- **Observe:** the Runbook revision/hash recorded in run archives created before and after each change, and revision resolution of previously sealed runs.
- **Pass iff:** every run archive records the exact Runbook revision/hash in force at its creation; an edit produces a new revision identity; a revert restores the earlier revision identity; archives sealed before later edits or reverts still resolve to their originally recorded revision.
- **Fail when:** a run records a wrong or missing revision, or a sealed run's resolved revision changes after a later Runbook mutation.
