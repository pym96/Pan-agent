# Skill packaging: SKILL.md, layered loading, and install scopes

- Type: verified-learning-fact
- Verification: source-located
- Source: local observation of `npx skills install jpoehnelt/skills/agent-dx-cli-scale` on 2026-08-17 (install output showed `.agents/skills/` placement, Claude Code symlink, and a universal multi-harness target list); skill frontmatter and discovery behavior as documented by the skills.sh tooling
- Updated: 2026-08-18

## Verified facts

- A skill is one directory containing its own `SKILL.md` (YAML frontmatter with `name`/`description` plus a Markdown body). There is no hand-maintained master index file of skills.
- The harness surfaces each installed skill's name and description at session start; the skill body is loaded on demand when the agent matches a task to the description (progressive disclosure).
- Install scopes differ: local installs land in the project's `.agents/skills/` (committable to the repo, project-scoped); global installs land in the user home (e.g. `~/.claude/skills/`) and apply across projects.
- `AGENTS.md`/`CLAUDE.md` are always-loaded project maps/rules; `SKILL.md` is an on-demand capability package for a reusable class of work, not for a single task.
- Corollary recorded from the same working session: the skills listing an agent sees is generated by the harness from installed frontmatter, not authored as a file.

## Boundaries

- Observed with one installer (skills.sh via npx) and the Claude Code/Codex harness pair; other harnesses may implement discovery, precedence, and scope rules differently.
- These are tool behaviors, not project invariants; the product must not depend on any specific skill-loading mechanism.
- Installing a skill imports third-party instructions into the trust boundary; content review (or a cleaner scan) remains the installer's responsibility.
