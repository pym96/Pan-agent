# Domain Docs

## Before exploring

- Read `CONTEXT.md` at the repository root.
- Read ADRs in `docs/adr/` that touch the area being changed.
- If either location is absent, proceed silently.

## Use the glossary vocabulary

Use domain terms exactly as defined in `CONTEXT.md` in issues, proposals, code, tests, and documentation. If a needed concept is absent, record the gap instead of inventing a near-synonym.

## Flag ADR conflicts

If proposed work contradicts an accepted ADR, surface the conflict explicitly and identify the ADR before proceeding.
