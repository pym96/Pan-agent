# #110 Stage A: confirmed-boundary recovery

Baseline: `11cf0e621004c8702408dfafd305dfd9e3ff8172`. Criteria1.0; Product, offline Faux only.

NativeKernel exports a private version-1 object only after the complete model response and every tool result settle. The object binds exact canonical messages, task, effective system/runbook prompt, tool definitions, provider/model/reasoning/adapter format, source run, next model exchange, cumulative counters and canonical usage. `GeneralAgentSession.resumeTask` admits a distinct Run Archive and calls the same Native loop without adding a user message. The default runTask path remains optional-checkpoint and backward compatible. A missing adapter capability is unsupported before any exchange. Adapter export/import is private and never a SessionObservation.

The application supplies two awaited durability barriers: commit, and invalidate before the next exchange. Node fsyncs artifacts and atomically replaces a mode-0600 checkpoint file. It sends only an ID/hash over stdout. Worker reads the fixed owned file, validates attempt ownership, and records exact bytes in PostgreSQL under the task lock. Only transaction commit sends an acknowledgement. The same lock arbitrates cancel, replacement, resume and completion. If persistence or acknowledgement fails, Node does not continue. Before the next model send the Worker transaction invalidates previous points. Later uncertainty therefore cannot roll back to an earlier point.

`POST /api/conversations/:id/tasks/:task/resume` accepts only requestId and checkpointId. DB records bind account, conversation, task, bundle and producer attempt. Resume requires a stopped active task, no cancellation, an eligible unconsumed point from the current attempt and matching authoritative bytes. It consumes the point and creates a separate execution identity atomically. Repeating the same request returns that identity. A queued resume remains cancellable/replaceable. New Node validates package tree, executor, image/resource configuration, context, schema, provider and adapter private state before sending; required regular output files are hash-verified and copied into the new attempt. Invalid imports are interrupted/unrecoverable with no new model/tool call. This is a finite confirmed-boundary feature, not arbitrary recovery or exactly-once execution.

Each execution has a separate owned root, PID and Run Archive. Stop confirmation includes Node exit, absence of the labelled task container, and existing RunArchiveStore stop-only recovery. Unsealed original event bytes are retained alongside an explicit recovery receipt; existing Product recovery seals them interrupted. Already sealed archives are unchanged. A resumed run never appends to its predecessor. Public attempt accounting sums actual model settlements by `(runId, turn)`, with unsettled or unavailable usage counted unknown. Cumulative Native totals are displayed separately and never summed across attempts.

## Private state and Kimi policy still requiring a later decision

Faux owns its versioned private cursor, script identity and synthetic continuation canary. A fresh adapter must import and validate that state. The canary is persisted only in protected checkpoint storage and the DB payload; public API/UI, Run Archive, Trace, stdout logs and CSV receive safe metadata/public context only. The application never reconstructs provider wire messages.

Real Kimi currently binds continuation to in-process WeakMap/message/session/signal identity. Those identities cannot be serialized meaningfully. A future adapter-owned design would need a versioned export of the exact provider continuation required for each tool-linked assistant message, message-to-private-state associations, provider/model compatibility identity and a new-process import procedure. Storing only canonical public messages would silently lose required reasoning continuation and is therefore rejected. This Stage A does not export, read or persist any real Kimi reasoning and does not change that adapter.

ADR-0015's no-private-reasoning-in-Run-Archive/public-projection boundary remains. A later Human/Master contract must explicitly decide whether separate private continuation persistence is permitted, allowed fields, encryption/key custody, owner-only access, retention/deletion including backups, incident handling, and provider-version invalidation. It must separately authorize live verification and budgets. Private persistence must not become a public archive field or appear in diagnostics. Until that decision and implementation, the missing checkpoint capability produces `checkpoint_provider_unsupported`.

The trusted local host/DB administrator can alter code and authoritative records. Hashes detect byte corruption and identity mismatches; they are not signatures against that administrator. HTTP users cannot choose paths, resource targets, private payloads or hashes. Docker retains read-only input, task-only output, no network/host credentials/socket and existing bounded resources.
