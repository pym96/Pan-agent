# What Pan enforces, and what it does not resume

Pan separates **model decisions** from **permission to execute them**. The model can propose a tool call or claim completion. The controller owns admission, timing and completion rules; process owners enforce the tested stop behavior; persisted records make interrupted work inspectable. Each has a different responsibility.

The public v0.1.9 package includes these mechanisms. The [onboarding checks](../../evidence/onboarding-system163/README.md) identify the installed artifact and the tested cases. The source links below explain the mechanism; the tests can disprove specific claims. They do not prove that every possible failure is recoverable.

## What happens at the time limit

Generation authority closes at the original exclusive deadline (`now >= deadline`). Stopping and preservation then have their own limits: a 2-second soft-stop grace, confirmation bounded by the existing 5-second path, finite verifier duration of 1–25 seconds, and a separate 30-second preservation watchdog. A frozen supervisor also has the caller's independent 4.5-second confirmation deadline. See [the execution design](../../design/execution-controller.md) for ownership and failure semantics.

These limits are enforced by code/process owners in the tested conditions. They do not make the whole CLI exit at exactly `--for`, or guarantee cleanup when the OS cannot schedule either owner. Read `execution.terminal.reason` and stop evidence instead of inferring success from elapsed time or exit code alone.

## After an interruption

1. Preserve the existing state, task archives and workspace; inspect the recorded execution.
2. Check recorded owned resources and uncertain side effects. Missing terminal evidence means unknown, even if a file looks correct.
3. Use the explicit sandbox reconciliation path when applicable. Do not erase old state to make a retry look clean.
4. Start a new execution only after deciding what effects are safe to repeat, using a new state directory and a newly bounded plan.

There is no installed `execution resume`, durable scheduler daemon, automatic restart after OS reboot, or general exactly-once tool-execution contract. The system already enforces admission and tested stopping and preserves evidence; automatic end-to-end task/schedule continuation remains a separate capability.
