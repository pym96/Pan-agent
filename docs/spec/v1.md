# [Spec] Workspace Agent Harness v1

## Problem

Tool-calling demos do not prove that an Agent can complete real workspace tasks reliably. They often lack a frozen task contract, objective grader, permission model, replayable Trace, recovery semantics, cost accounting, and a controlled baseline. The project has eight weeks and must produce inspectable evidence for large-model / Agent algorithm-engineering internships.

## Product

Build a single-user, local-first **Local Workspace Agent**. A user supplies a goal and an isolated fixture workspace. The Agent may read, search, and modify Markdown, CSV, and code through allowlisted tools, compose versioned Skills/Workflow, and return one terminal RunResult with a structured Trace and deterministic grader verdict.

Coze is a **Product Reference** for organizing task entry, Skills, Workflow, tools, execution state, observation, debugging, evaluation, and release. It is not a benchmark and no claim may compare scores against Coze.

## User stories

1. As a user, I can run a versioned Workspace Task from the CLI and receive exactly one terminal RunResult.
2. As a user, I can inspect a Trace containing model/tool activity, budgets, workspace effects, grader result, and terminal reason.
3. As a user, I can pause or recover a Task Run without silently duplicating a non-idempotent effect.
4. As a user, I can see a requested path or command rejected when it exceeds the task policy.
5. As a developer, I can replace the model Adapter or Tool without changing AgentLoop.
6. As a developer, I can compose versioned Skills and Workflow without hiding control flow in an unreviewable prompt.
7. As an evaluator, I can grade the final fixture workspace without allowing the Agent to modify the grader.
8. As an interviewer, I can reproduce a released result from a clean clone and trace every resume number to raw artifacts.

## v1 Evaluation Suite

- Exactly 30 version-frozen tasks: 10 Markdown knowledge/cross-file maintenance tasks, 10 CSV retrieval/cleaning/aggregation tasks, and 10 code-change/test-repair tasks.
- Every task contains a versioned isolated fixture workspace, policy, budget, deterministic grader, gold result, broken baseline, and hashes.
- Tasks and graders freeze before formal experiments; failed cases are retained.
- Primary metric: task success rate.
- Secondary metrics: input/output Token, estimated cost, and end-to-end latency.
- Reliability metrics: fault-injection recovery rate, unauthorized-operation block rate, and Trace completeness.

## Baseline and iteration

The Minimal ReAct Baseline and Full Harness System use the same model, tools, tasks, prompt budget, and graders. Full adds only Skills/Workflow, Trace, recovery, and reliability controls. Raw results must rebuild every summary.

After the first full comparison, select one failure mode repeated across tasks, preregister a falsifiable mechanism and controlled variables, then run one mechanism on/off ablation. Null, negative, and uncertain outcomes remain in the report.

## Acceptance criteria

1. A mock HTTP server covers non-streaming, streaming, 429, 5xx, timeout, and secret-redaction behavior; one budgeted live-provider smoke run is archived.
2. CLI and allowlisted tools complete six seed tasks, two per task family, with fixture, grader, Trace, diff, and RunResult.
3. At least three versioned Skills and an explicit Workflow have contract and permission-negative tests.
4. Checkpoint/resume, timeout, output limit, path escape, undeclared command, interruption, cleanup, and budget paths have deterministic tests.
5. The 30-task suite passes count/category/hash/gold/broken checks before formal runs.
6. Minimal ReAct and Full results exist for the frozen suite under identical model/tool/task/budget settings.
7. One preregistered mechanism iteration has raw on/off results and retains null or negative outcomes.
8. v1 tag, CI, quickstart, known limitations, representative Trace, five-minute demo, and clean-environment reproduction report are public.

Only after all eight criteria pass may v1.1 attempt a clearly named Terminal-Bench subset. BFCL is an on-demand component diagnosis for tool-selection or argument errors. GAIA is excluded from the current eight-week roadmap.

## Delivery order

- Week 1--2: repository migration, real Adapter, CLI, allowlisted tools, six seed tasks.
- Week 3--4: Skills/Workflow, budgets, checkpoint/recovery, fault injection, policy, and frozen 30-task suite.
- Week 5: Minimal ReAct vs Full comparison.
- Week 6: one failure-driven mechanism iteration and ablation.
- Week 7: public v1, CI, demo, artifacts, and clean-environment reproduction.
- Week 8: applications and interviews; try Terminal-Bench only if v1 passed.

## Learning evidence

The Markdown Learning Wiki contains index.md, append-only log.md, source/concept/experiment/failure/decision/question pages, and Ingest/Query/Lint rules. It is auditable learning evidence and content material, not a product feature or benchmark.

## Research allocation

Plan A is active: pause active pursuit of a second paper and prioritize the Agent project. Plan B may emerge only after MVP/baseline completion reveals a repeated, falsifiable failure mode with a public benchmark, strong baseline, controlled variables, and no delivery delay. Plan C, the new 3DV idea, is frozen. BVI remains protected existing evidence and receives no new 3DV experiments.

## Out of scope

- Open-web browsing, GUI/Computer Use, multimodal input/output.
- Autonomous research, model training, a precommitted paper, or a new 3DV experiment.
- Cloud multi-tenancy, hosted SaaS, complete Coze cloning, a workflow marketplace.
- GAIA coverage or any unsupported official/leaderboard benchmark claim.
- Desktop Wiki UI, vector search, knowledge graph, multimodal parsing, or MCP for the Wiki.

## Current verified state

The repository currently has AgentLoop.run(Task, RunLimits) -> RunResult, replaceable model/tool interfaces, seven terminal statuses, JSONL Trace behavior, and 14 deterministic standard-library behavior tests. Real provider, CLI, allowlisted workspace tools, Skills/Workflow, checkpoint/recovery, the 30-task suite, baseline results, CI, and v1 release are not yet implemented.
